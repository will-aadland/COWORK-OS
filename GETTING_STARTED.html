Promega CoWork OS

Getting Started Guide

A Claude plugin plus a Windows Electron desktop app that turns your work — projects, meetings, notes, transcripts — into folders on disk and visualizes them as cards. Claude reads and writes the same folders the Visualizer displays. This page walks you through the seven steps to go from zero to a working setup.

Plugins: promega-workspace v1.0.0 · promega-workspace-engineering v5.0.0 Visualizer: Promega Project Planner V3.0.4 Marketplace: will-aadland/cowork-os (GitHub)

How it works

Two pieces work together. The Claude plugin gives Claude tools to read and write files in a folder on your computer. The Visualizer is a Windows Electron app that reads the same folder and shows your work as a card grid and calendar. The plugin defines the folder shape both pieces expect.

Claude (chat) Plugin installed; reads and writes files in your CoworkOS folder directly
Folders on disk Personal Workspace/ with Projects/, Meetings/, etc. The folders ARE the data.
Visualizer Windows Electron app. Reads the same folders. Renders them as cards and a calendar.

There is no database, no cloud sync, nothing magical — just markdown files in folders. You can edit them in VS Code, the Visualizer UI, or by talking to Claude. All three see the same data instantly.

No localhost, no API. The Visualizer is a single-process Electron app. There is no URL to visit, no localhost server, no API for Claude to call. Claude and the Visualizer don't talk to each other — they both read the same folders. The Visualizer's file watcher picks up Claude's writes within about 200 ms.

Step 1Create your CoworkOS folder

1

Pick a location and create the folder

This is the parent folder Claude will read and write to. Everything the plugin creates goes inside it. Put it somewhere you can find quickly — somewhere that also backs up.

Recommended location:

C:\Users\[your-username]\OneDrive\Desktop\CoworkOS

Other options that work fine:

  • C:\Users\[you]\OneDrive\Documents\CoworkOS
  • C:\Users\[you]\Documents\CoworkOS (local only, no cloud backup)
OneDrive note. If CoworkOS is in OneDrive, the first time the Visualizer reads each file there may be a 1–2 second hydration pause while OneDrive pulls the file local. After that it's fast.

Don't put CoworkOS inside another sync app's root (Dropbox, Box, Google Drive). Pick one cloud backup, stick with it.

Step 2Add it to Claude as a favorite

2

Mount the folder so Claude can see it

Claude Code needs to know where your CoworkOS folder is so it can read and write files there.

  1. Open Claude Code (desktop app or web).
  2. In the workspace or folder selector, click Add a folder.
  3. Browse to your CoworkOS folder and select it.
  4. Click the star (Favorite) so Claude Code remembers it across sessions.

Claude should now have read/write access to everything inside CoworkOS.

Quick test. Type list the files in my workspace. Claude should be able to look inside CoworkOS even though it's empty right now.

Step 3Install the plugin

3

Choose your plugin and install it from the marketplace

The CoWork OS marketplace lives on GitHub at will-aadland/cowork-os. You add the marketplace once, then install whichever plugin fits your role. Both plugins require the Microsoft 365 Plus connector for meeting sync and SharePoint search.

Step 3a — Pick your plugin

For everyone promega-workspace

Works for any Promega employee — scientists, lab technicians, QA, manufacturing, operations, sales, HR, IT, management. Generic workspace setup with Projects, Meetings, and any custom workspaces you want. Meeting sync, SharePoint search, save-note, save-summary.

For engineers promega-workspace-engineering

Everything in the general plugin plus engineering-specific defaults: Change Controls, DS Revisions, and Commissioning workspace options; ISA-88 / FactoryTalk Batch reference skill; engineering SharePoint areas pre-configured.

Not sure which one? If you're a process engineer, automation engineer, or work on PLCs and batch systems, use the engineering plugin. Everyone else, use the general one. You can switch later without losing any workspace data.

Step 3b — Install from the marketplace

  1. Open Claude Code. Click Customize.
  2. Next to Personal plugins, click the +.
  3. Click Add a marketplace.
  4. Paste the marketplace URL: 
    will-aadland/cowork-os
  5. Confirm. Claude Code loads the marketplace.
  6. Expand cowork-os. Click your plugin from Step 3a.
  7. Click Install. Restart Claude Code if prompted.

Verify. Type / in chat. You should see /begin, /add-project, /add-workspace, /save-summary, /save-note.

Step 3c — Connect Microsoft 365 Plus

Both plugins use the Microsoft 365 Plus connector for Outlook calendar sync, transcript pull, and SharePoint search.

  1. Open Claude Code → Customize → Connectors.
  2. Find Microsoft 365 Plus (also listed as Microsoft 365 Open Beta).
  3. Click Connect and sign in with your Promega Microsoft account.
You don't need to do this before /begin. The connector is only needed for meeting sync and SharePoint search. You can connect it after running /begin. If Claude prompts you to connect it during a sync, just follow the prompt in the chat.

Update later

  1. Go to Customize → Personal plugins → cowork-os → your plugin.
  2. Click Update. Restart if prompted.

If no update shows, hit the marketplace Refresh control first.

If the marketplace install fails

If you see "Cannot reach marketplace", "Network error", or similar, Claude Code can't reach GitHub — usually a firewall or VPN issue. Install from a local copy instead.

Install from a local clone

  1. Get the repo. Either:
    • git clone https://github.com/will-aadland/COWORK-OS.git, or
    • On GitHub, click Code → Download ZIP and extract it (e.g. to %USERPROFILE%\Documents\COWORK-OS\).
  2. Open Claude Code's local plugins folder: 
    %USERPROFILE%\.local-plugins\marketplaces\local-desktop-app-uploads\

    Create the folders if they don't exist.

  3. Copy your plugin folder in. From the cloned repo, copy either promega-workspace\ or promega-workspace-engineering\ into local-desktop-app-uploads\. The final layout: 
    %USERPROFILE%\.local-plugins\
└── marketplaces\
    └── local-desktop-app-uploads\
        └── promega-workspace\          (or promega-workspace-engineering\)
            ├── .claude-plugin\plugin.json
            ├── commands\
            └── skills\
  4. Fully quit Claude Code (system tray → Quit) and re-open.
  5. Verify. Type /. You should see /begin.

Troubleshooting

  • Marketplace not found. Check spelling: will-aadland/cowork-os (lowercase, hyphen). Still failing? Use the local install workaround.
  • No commands appear after install. Restart Claude Code. Then check Customize → Personal plugins — if your plugin isn't listed, the install didn't take.
  • Microsoft 365 Plus not appearing in Connectors. It may be listed as "Microsoft 365 Open Beta." If it's not there at all, check that your Claude plan includes connector access.
  • Both plugins installed by mistake. Go to Customize → Personal plugins and uninstall the one you don't want. Running both duplicates the slash menu.
Install only one plugin. promega-workspace and promega-workspace-engineering have overlapping commands and trigger phrases. Installing both causes duplicate completions and unpredictable routing. Pick the one that fits your role.

Step 4Run /begin

4

One-time workspace setup (about 5 minutes)

Type /begin in Claude. The plugin walks you through how the system works, asks one question, builds your Personal Workspace, and gives you a Personal Preferences block to paste into Claude Settings.

What happens during /begin:

  • System orientation. Claude explains how CoWork works, what a workspace is, and why having more in here makes Claude more useful over time.
  • One question. Your name, role, and any workspaces you want beyond Projects and Meetings. That's it — no interview.
  • Your CoWork folder path. Claude asks for the path you created in Step 1.
  • Scaffold. Creates Personal Workspace/ with all your workspaces.
  • Folder tour. Claude briefly explains what was built and tells you to pin CoworkOS to Quick Access in Windows Explorer.
  • Personal Preferences block. A comprehensive block to paste into Claude Settings so Claude always knows about your workspace — in every conversation, automatically.
  • Meeting sync setup. Claude walks you through scheduling meeting-sync as a daily task (covered in depth in Step 5).

After /begin, your folder structure looks like this:

CoworkOS\
└── Personal Workspace\
    ├── CLAUDE.md              # workspace context and mount paths — Claude reads this first
    ├── Projects\
    │   └── Completed\
    ├── Meetings\
    ├── Notes\               # workspace-level notes
    ├── [Your workspace]\   # e.g. Change Controls\, Experiments\, Protocols\
    │   └── Completed\
    └── ...

The Personal Preferences block. Paste the block Claude generates into Claude Settings → Personal Preferences (or Custom Instructions, depending on your interface). This is what makes Claude workspace-aware in every conversation — it won't ask where things are or forget about your workspace. The block covers your workspace path, all your workspaces, routing rules, available commands, and behavior rules.

/begin is run once. If you need to add a workspace later, use /add-workspace. If you want to regenerate your Personal Preferences block (e.g., after adding new workspaces), just ask Claude: "Regenerate my Personal Preferences block."

Step 5Schedule meeting-sync daily

5

Set meeting-sync to run automatically each morning

The meeting-sync skill pulls your Outlook calendar into the Meetings\ workspace. Running it daily keeps everything current without you thinking about it.

Set it up in Claude Code Settings → Scheduled Tasks:

  1. In Claude Code, open Settings.
  2. Go to Scheduled Tasks (or Background Tasks, depending on your version).
  3. Add a new task:
    • Command: /meeting-sync
    • Schedule: Daily, weekdays — 7:00 AM recommended
    • Model: Sonnet (handles calendar parsing and transcript summarization efficiently)
  4. Save the task.

Or just say it in plain language and Claude will set it up:

Schedule meeting-sync to run every weekday at 7am using Sonnet

What it does every morning:

  • Pulls Outlook events for this workweek and next workweek (Mon–Fri, two weeks).
  • Creates or updates a folder for each meeting using the YYYY-MM-DD — Title naming convention.
  • Writes the agenda, attendees, date, time, and location into each meeting's CLAUDE.md.
  • Automatically pulls and summarizes transcripts from yesterday's recorded Teams meetings.
  • Updates Meetings\OOO.md with any out-of-office time.
  • Quietly removes folders for cancelled meetings.

You can also trigger it manually at any time by typing sync my meetings or /meeting-sync. Manual runs are interactive — Claude will ask before doing anything destructive.

Transcript access. Transcripts are available for Teams meetings you organized or were a presenter in. For meetings where you were just an attendee, transcript access depends on the organizer's settings. If a transcript isn't available, meeting-sync logs it and moves on — it won't fail the whole sync.

Step 6Install the Visualizer

6

Run the Promega Project Planner installer

The Visualizer is a self-contained Windows app distributed as a single .exe installer. It bundles everything it needs — you don't have to install Node, Electron, or anything else separately.

Windows will warn you twice. Both warnings are expected and safe to bypass. The installer isn't signed by a commercial certificate authority, so Windows flags it as "unknown publisher." It's the same file your teammates are using — it just doesn't carry a signature Microsoft recognizes. Details on what to do are in the steps below.
  1. Download the installer. Get it from the team distribution channel or the GitHub releases page: 
    Promega Project Planner Setup 3.0.4.exe   (~78 MB)
  2. Warning #1 — the browser may block the download.

    Edge or Chrome may show a warning that the file "isn't commonly downloaded" or "could harm your device."

    • Edge: Click ··· next to the blocked download → Keep → Keep anyway.
    • Chrome: Click the ^ caret next to the blocked download → Keep.
  3. Save to Downloads or Desktop.
  4. Warning #2 — Windows SmartScreen ("Windows protected your PC").

    Double-clicking the .exe brings up a blue full-screen dialog:

    Windows protected your PC

Microsoft Defender SmartScreen prevented an unrecognized
app from starting. Running this app might put your PC at risk.

[Don't run]

    This is expected. Here's how to proceed:

    1. Click the small More info link near the top of the blue dialog.
    2. The dialog expands and shows the app name and Unknown publisher.
    3. A Run anyway button appears. Click it.

    Why this is safe: SmartScreen flags any executable that isn't signed by a recognized CA or widely distributed. Internal Promega tools fail both checks — same as any in-house app. It does not mean the file is malicious. If you want to double-check: verify the file size matches (~78 MB) or confirm with your team lead before running.

  5. The installer opens.
    • Default install path: %LOCALAPPDATA%\Programs\Promega Project Planner
    • Check Create desktop shortcut and Create Start menu shortcut.
  6. Click Install. Takes about 10 seconds.
  7. Launch from Start menu or desktop shortcut.

On first launch you'll see a blank calendar. Step 7 walks you through connecting it to your workspace.

Updates. There's no auto-updater. When a new version ships, download the new .exe and run it over the existing install. Your data and config are preserved. You'll see the same two warnings again — same procedure each time.

Step 7Connect folders in the Visualizer

7

Connect the Visualizer to your Personal Workspace

The Visualizer reads folders directly from disk. You configure it once by pointing each section at the right folder.

  1. Launch the Visualizer. A blank calendar appears — that's expected.
  2. Click the ⚙ Settings gear icon in the top-right header.
  3. Under "Section Folders," configure each path:
    • Meetings Folder → click the 📁 browse button → navigate to CoworkOS\Personal Workspace\Meetings\
    • Files Root → browse to CoworkOS\Personal Workspace\
    • Project folders → click "Add Mount" for each workspace that holds projects. Add them one at a time: 
      CoworkOS\Personal Workspace\Projects\
CoworkOS\Personal Workspace\Change Controls\   (if you have one)
CoworkOS\Personal Workspace\[Other workspace]\  (repeat for each)
  4. Each path saves automatically when you pick it — no Save button needed. The project list updates immediately.
  5. Close Settings. Your workspaces appear in the calendar and project list.
Which workspaces to add as project mounts? Add any top-level workspace folder that contains project items — that is, any folder whose subfolders each have a Completed\ subfolder inside them. Meetings go in the Meetings field, not as a project mount.

You're all set. As soon as meeting-sync runs (or you add your first project), cards will appear.

Live reload. The Visualizer watches the folder tree. Any file Claude writes — a new note, a synced meeting, a saved summary — appears in the UI within about 200 ms. No refresh button needed.

The six tabs:

  • Calendar. Month grid with project bars and meeting chips, colored by priority and title.
  • All Projects. Filterable list grouped by status across all workspaces.
  • All Meetings. Reverse-chronological. Today's meetings highlighted.
  • Files. Sidebar tree plus main pane. Drag-drop, preview, edit.
  • Summaries. Time-window summary builder for weekly and monthly digests.
  • Settings. Workspace root, per-workspace paths, priority colors.

Commands reference

Five slash commands. Type / in Claude to see the full list. Most also fire on natural language, but the slash form is the canonical entry point.

cmd /begin

One-time setup. Explains the system, asks your name, role, and what workspaces you want, then scaffolds Personal Workspace\ and generates a comprehensive Personal Preferences block. Run once. No interview — just one question and go.

When to run: Once, the first time you use the plugin.
cmd /add-workspace

Adds a new top-level workspace folder (like Experiments\ or Protocols\) to your Personal Workspace and registers it in your CLAUDE.md mounts list. For adding items inside a workspace, use /add-project.

Trigger phrases: "add a workspace", "create a workspace for [X]", "I need a workspace for [X]", "new workspace"
cmd /add-project

Scaffolds a new item inside any workspace with the canonical schema (CLAUDE.md with metadata block, Notes\, Chat Summaries\, Files\). Asks for name, description, and which workspace. Does not create meetings — those come from meeting-sync.

Trigger phrases: "new project", "start a project", "add a CC", "new change control", "new folder for [X]", "track a new [X]"
cmd /save-summary

Saves a summary of the current Claude conversation into the right project's Chat Summaries\ folder and adds a pointer to ## Recent Summaries in the project's CLAUDE.md. Call this when you've covered something worth keeping.

Trigger phrases: "save this chat to [project]", "summarize this conversation", "capture this for [project]"
cmd /save-note

Saves a discrete note into the right project's Notes\ folder. Captures your words verbatim when you're specific. When vague ("remember this"), asks what to save or pulls from the last few messages.

Trigger phrases: "save to notes on [X]", "note that...", "remember this", "log this", "make a note that...", "create session notes"

Skills reference

Skills fire automatically on natural-language phrases. You don't need to type a slash command — just say what you mean.

skill meeting-sync

Pulls Outlook calendar events into Meetings\ for this workweek and next. Converts times to Central (America/Chicago). Each meeting gets a folder with title, date, attendees, agenda, and eventually a transcript summary. Skips cancelled, Hold, and OOO events (OOO goes to OOO.md). Pulls Teams transcripts and writes 300–600 word summaries into ## Transcript Summary.

Two modes: scheduled (runs silently, auto-pulls yesterday's transcripts) and interactive (asks before deleting cancelled folders, asks which transcripts to pull).

Trigger phrases: "sync my meetings", "pull my calendar", "update my meetings", "sync my calendar", "update OOO"
skill save-note

Skill counterpart to the /save-note command. Same logic, fires on natural-language triggers without needing the slash prefix.

Trigger phrases: "save to notes", "note that...", "remember this", "don't forget", "log this", "make a note", "jot this down"
skill sharepoint-search

Three-tier knowledge search for Promega-specific questions. Always checks your Personal Workspace first, then Promega's SharePoint, then general knowledge. Cites sources. Never fabricates — if both workspace and SharePoint are empty for a Promega-specific question, it says so.

Trigger phrases: "search SharePoint", "where's the procedure", "look it up", "what's our process for", "find the form for", "check the knowledge base"
skill isa88-guide Engineering only

ISA-88 batch model reference tuned to Promega's FactoryTalk Batch / PhaseManager implementation. Covers the batch model hierarchy (Recipe / UP / OP / Phase / EM / CM), Phase state machine, CM tag naming, recipe types, and a worked FERMB P6 example. Includes the full reference document.

Trigger phrases: "ISA-88", "S88", "batch model", "PhaseManager", "Equipment Module", "Phase state machine", "FactoryTalk Batch"

Workspace layout

Inside Personal Workspace\, every item is a folder with a known shape. Claude reads and writes these files; the Visualizer renders them.

Project items (any workspace)

[Item Name]\
├── CLAUDE.md              # title + description + ## Planner Metadata block
├── Notes\               # human notes, one .md file per note
├── Chat Summaries\      # Claude-generated summaries (/save-summary)
└── Files\               # any attachments (docx, xlsx, pdf, screenshots)

Meeting items (Meetings\ workspace only)

YYYY-MM-DD — [Meeting Title]\    # em-dash (U+2014), not a hyphen
├── CLAUDE.md              # ## Planner Metadata + ## Meeting Details + ## Attendees + ## Agenda + ## Transcript Summary
├── Notes\               # your meeting notes
├── Files\               # attachments
└── Transcripts\         # raw transcript file (transcript.md)
Meetings do not have a Chat Summaries\ folder. Claude-generated meeting summaries go into the meeting's ## Transcript Summary section in CLAUDE.md instead.

The CLAUDE.md metadata block

Every project and meeting CLAUDE.md has a strict metadata section the Visualizer reads. Edit it carefully — always use the Edit tool, never a full rewrite, no blank lines inside the block:

# [Item Name]

[Optional one-paragraph description.]

## Planner Metadata
status: on-track          # on-track | at-risk | behind | blocked | completed | on-hold
priority: medium          # high | medium | low
startDate: 2026-04-23
endDate:   2026-05-15
progress:  0              # 0 to 100
stress:    0              # 0 to 5
color:     #d46a35        # hex color for the Visualizer card
isMeeting: true           # meetings only
links:
  - url: https://example.com
    label: Display name

Setting status: completed triggers the Visualizer's auto-archive into [workspace]\Completed\. Reverting status moves it back.

Daily usage

Once everything is set up, your daily workflow looks like this.

Morning

  • Scheduled meeting-sync ran at 7 AM. Today's and tomorrow's meetings are in Meetings\, already organized with attendees and agendas. Yesterday's recorded meetings have transcript summaries.
  • Launch the Visualizer from the Start menu or desktop shortcut. Glance at the calendar — see what's coming.

During work

  • Working through a problem in Claude? Say "save this chat to [project]" when you reach a decision or insight you want to keep (/save-summary).
  • Found something worth remembering? Say "note that [finding]" (/save-note).
  • Starting a new initiative? Say "add a project for [name]" (/add-project).
  • Need a new category of work? Say "add a workspace for Protocols" (/add-workspace).
  • Looking for a Promega procedure or form? Just ask. Claude searches your workspace first, then SharePoint, and tells you which tier the answer came from.

End of week

  • Open the Visualizer's Summaries tab.
  • Pick "This Week" or a custom date range and click Save Summary. A markdown file lands in your workspace.
  • Finished something? Set its CLAUDE.md to status: completed — the Visualizer auto-archives it to Completed\.
The more you put in, the more useful Claude becomes. Context from past projects, meeting transcripts, saved notes — Claude finds all of it automatically when you ask a question. Every note and summary makes the next conversation smarter. The data is plain markdown on your disk — nothing locked in, nothing proprietary.
